# HANDOFF：Decode to Finish Synchronization 弱包接收机

**更新时间：** 2026-08-20  
**主仓库：** `D:\Desktop\proj\gr-lora_sdr`  
**当前主线：** CRC-aided ambiguity-ridge list synchronization + bounded soft-Hamming decoding  
**实验范围：** 单天线、单网关、单次空口发送；不依赖重传、重复符号、多天线或多网关合并

## 0. 一句话交接

> 当前最有价值的方法不是恢复高采样率，也不是继续修改单个 FFT 判决，而是把 LoRa 弱包接收从 `hard synchronize -> decode` 改成 `ambiguity-ridge sync list -> Savaux likelihood + FEC -> CRC arbitration`：不要在解码前过早杀死同步候选，让解码完成同步。

当前 Python 原型和完整 packet-level 实验已经跑通。8 个真实 OTA capture、10 个 AWGN seed、10--16 dB 共 560 个 trial 中，ridge K=4 加 bounded soft-Hamming 相比同一 ridge 的 hard decoder 从 309/560 提升到 370/560；PDR50 所需 Es/N0 从 12.500 dB 降到 11.676 dB。相对原始 strict receiver，PDR50/PDR80 分别改善约 2.04/2.55 dB。

这已经是一条完整方法，但还不能直接写成最终论文结论：只有 8 个独立物理 capture；尚未公平对比 gr-lora_sdr 自带 soft decoder、NELoRa/NELoRa++、Ameloot 等单网关弱信号接收方法；而且 PHY CRC 在极低 SNR 下出现过一次错误交付。

## 1. 解决的问题

弱包损失来自两个串联的 hard decision。

### 1.1 FrameSync 过早拒收

原始链路要求前导码先给出唯一 CFO/STO 坐标并通过全部 gate，才允许 payload decoder 运行：

```text
preamble -> one sync coordinate -> hard validation -> payload decode
```

真实 noisy-FrameSync audit 发现，部分 `strict_invalid` 包已经有足够好的 CFO/STO/SFO，Savaux + FEC 可以把 payload 完整解出，但 `preamble_all_bin0`、netID 或 locator 等 gate 提前把包丢掉。15 dB 的早期实验甚至出现 `estimate_available=100%`、候选可完全解码，但 strict PDR 只有 75% 的情况。

### 1.2 Symbol Argmax 丢弃编码可利用的证据

Savaux 为每个 symbol 产生完整匹配滤波频谱。hard path 只保留最大 bin：

```text
full spectrum -> Argmax -> symbol -> hard Hamming
```

低 SNR 下经常是 wrong bin 只比 true bin 高一点。Argmax 后，后级 Hamming 看不到 true bin 仍有较大似然。当前 soft path 保留完整频谱，把 Hamming 合法码字约束用于 symbol 判决。

## 2. 当前方案

完整链路是：

```text
complete 1 MS/s IQ packet
  -> noisy FrameSync
  -> original coordinate + Top-K ambiguity-ridge coordinates
  -> Savaux full spectrum for every header/payload symbol
  -> LoRa semantic-symbol likelihood
  -> interleaved bit likelihood
  -> bounded Hamming ML (16 valid codewords per nibble)
  -> explicit header + payload deinterleave/dewhiten
  -> PHY CRC arbitration
  -> selected sync coordinate and payload
```

### 2.1 Ambiguity-ridge sync list

Candidate 0 永远保留当前 noisy FrameSync 坐标。其余候选从 SFD2 chip-rate FFT 的强峰中产生，不做 CFO x STO 二维网格暴搜，而使用 LoRa chirp 的近似耦合关系：

```text
delta_payload_samples ~= OSR * delta_CFO_bins
```

每个候选随后独立进行 fractional-STO/SFO refinement。当前默认：

```text
K = 4
SFD peak pool = 32
```

候选按物理证据排序，payload CRC 成功后 early stop。

### 2.2 Bounded soft-Hamming

每个 Savaux spectrum 先映射为 LoRa semantic-symbol log score，再 marginalize 成 bit log probability。每个 deinterleaved Hamming codeword 只枚举 16 个合法 nibble：

```text
complexity = 16 codewords / decoded nibble
```

没有 payload beam search，没有 CRC-state 搜索，不枚举完整 payload。expected bytes 只在 CRC 之后用于 exact-delivery 和 collision audit，不参与候选选择。

### 2.3 Decoder-in-the-loop arbitration

前导码 gate 从最终生死裁决降为候选生成/排序证据。每个 sync hypothesis 进入完整 header/FEC/dewhitening/CRC 链，首个 payload-CRC success 被选择。

当前最合适的概念名称：

```text
Decode to Finish Synchronization
```

工作名称可以使用：

```text
RidgeSync-SH
CRC-Aided Ambiguity-Ridge List Synchronization with Soft-Hamming Decoding
```

## 3. 现在真正可以主张的创新点

1. **发现：premature synchronization rejection。** 弱包并不总是没有可用同步信息；传统 hard validation 会丢掉 downstream decoder 已经能够验证和恢复的包。
2. **LoRa-specific list synchronization。** 利用 CFO/STO ambiguity ridge 将二维同步 uncertainty 压缩成少量一维物理候选，而不是通用 CFO x STO 暴搜。
3. **Decode to finish synchronization。** 用完整 payload FEC/CRC 反向完成同步坐标选择，把 synchronize-then-decode 改成 list-synchronize-then-decode。
4. **有界的同步/编码联合判决。** Savaux 全谱证据进入每个 Hamming codeword 的 16 状态 ML 判决，避免旧 payload beam 的组合爆炸。

必须保持诚实：**soft decoding 本身不是创新。** 当前 gr-lora_sdr 已有 `soft_decoding=True` 的 FFT-demod/deinterleaver/Hamming 链。论文 novelty 应放在 ambiguity-aware sync list 和 decoder-in-the-loop synchronization；bounded soft-Hamming 是当前联合实现和低复杂度落地点。下一轮必须先与原生 soft chain 公平对比。

## 6. CRC 安全边界

560 trial 中两条 decoder family 各出现一次不同的 CRC-valid wrong packet：

```text
hard ridge:
  exp0_000000_rxg20_0_fulltrim:13:20260827

soft ridge:
  exp0_000005_rxg20_0_fulltrim:11:20260821
```

soft decoder 修正了 hard decoder 的 13 dB collision，但在接近随机判决的 11 dB 产生了另一条 collision。12--16 dB 的 soft path 没有错误交付。

因此不能写“CRC 保证 list search 安全”。部署时至少需要其中一项：

- calibrated sync/decoder reliability floor；
- LoRaWAN MIC；
- 自定义 CRC32/更强完整性字段；
- 多个独立 decoder evidence 的一致性仲裁。

报告必须同时给 `CRC accept rate` 和 `exact delivery PDR`。

## 7. 已经探索但不再作为 AWGN 主线的方向

### 7.1 LiteNap/欠采样

纯 AWGN 下减少样本会丢失证据。主要错误是 aliased modulo-bin 本身选错，不是 alias group 选错。它适合计算量/采样率 tradeoff，不是超过 full-sample Savaux 的灵敏度方法。

### 7.2 RF super-resolution

插值 + 低通已经吃掉主要收益。CNN 前端尚未证明在相同 250 kSPS 输入上优于作者插值 + Savaux；不应把插值处理增益描述为创造新信息。

### 7.3 Multi-rate representation

同一 1 MS/s waveform 的 500/250/125 kSPS 分支高度相关。covariance-correct 结果没有独立 AWGN 增益；可以作为 error forensics，不作为主 decoder。

### 7.4 AliasTrim / robust sparse

它们针对 CW、spur、窄带 blocker 等结构化干扰。纯 AWGN gate 基本不打开，退化为 Savaux。可留作 interference extension，不应进入当前 AWGN headline。

### 7.5 小范围 residual-CFO bank

真实 FrameSync residual CFO 大多不落在 Savaux 的致命区；实际主要损失来自 hard gate 和同步坐标 jump。普通 `{-0.5,...,+0.5}` CFO bank 已降级，不是主创新。

## 9. 下一步：对单天线、单次发送弱包方法做统一冲锋

### 9.1 第一优先级：先打仓库自带 soft decoder

这是必须立即完成的公平性检查。当前 gr-lora_sdr 已实现：

```text
fft_demod(soft_decoding=True)
-> Gray LLR
-> soft deinterleaver
-> soft Hamming decoder
```

下一实验必须在相同 noisy IQ、相同 sync coordinate、相同 FEC/CRC 和相同 seed 上比较：

```text
A  upstream hard decoder, candidate 0
B  upstream native soft decoder, candidate 0
C  current bounded soft-Hamming, candidate 0
D  ridge K=4 + upstream native soft decoder
E  ridge K=4 + current bounded soft-Hamming
F  oracle-sync versions of B/C
```

缺失的关键消融是 `candidate-0 soft`：当前已有 ridge-soft 和 soft-oracle，但尚未把“soft decoder gain”与“ridge alternative gain”在 noisy candidate 0 上完全拆开。

如果 C/E 不能超过 B/D，不能把 soft-Hamming 当贡献；主线仍可保留 ridge list + downstream CRC arbitration。

### 9.2 第二优先级：论文级直接对手

只纳入单网关、单天线、单次原始 LoRa packet 可运行的方法：

1. **Standard dechirp FFT + gr-lora_sdr hard/soft FEC。** 最基本且必须完整端到端。
2. **Savaux oversampled demodulation。** 当前强 classical demod baseline。
3. **Ameloot et al., “LoRa signal synchronization and detection at extremely low SNRs”。** 它同时改 detection、synchronization 和 symbol detection，是最接近当前系统目标的 classical receiver 对手。
4. **NELoRa / NELoRa-Bench。** 单网关 neural-enhanced symbol demodulation；公开 benchmark 报告相对 standard decoder 约 1.84--2.35 dB。先在其 SF7--10 benchmark 上复现，再扩到共同 OTA 设置。
5. **NELoRa++。** 单网关 dual-channel spectrogram + dual-DNN，论文报告跨配置约 0.50--2.75 dB；需要严格做 capture/session group split，禁止同一 clean capture 的不同 AWGN seed 跨 train/test。
6. **LZn single-user mode。** 虽然方法也支持 collision，但其 spectral-intersection synchronization 可作为纯弱包 sync baseline；比较 candidate availability、detection probability 和完整 CRC PDR。
7. **经典 CFO/STO 联合/迭代同步。** 用 Ghanaatian/Afisiadis receiver analysis 作为非学习同步基线。

参考入口：

- NELoRa paper DOI: `10.1145/3485730.3485928`
- NELoRa-Bench: `https://arxiv.org/abs/2305.01573`
- NELoRa++: `https://www.cse.msu.edu/~caozc/papers/nelora-ext-Maolin.pdf`
- Ameloot receiver: `https://doi.org/10.1109/JIOT.2021.3137598`
- LZn: `https://netd.cs.tu-dresden.de/pub/asw-lrlfs-26.html`
- LoRa receiver analysis: `https://arxiv.org/abs/1811.04146`

### 9.3 明确排除的“非公平增益”

当前论文 scope 不与下列方法争绝对 SNR headline：

- 多天线/多 gateway coherent combining，例如 Charm、NScale 类空间合并；
- 重传、同一 packet 多次接收或跨包 combining；
- 修改发射端并用多个 symbol 表示一个 symbol，例如 SFusion；
- 多用户同时发送、collision/MPR，例如 CoLoRa、FTrack、AlignTrack、LoRaPDA；
- 改变 SF/BW/CR 或增加空口冗余后声称 receiver gain。

它们可以放 related work，但不能和当前单次接收方法直接比较 dB。

## 10. 统一 benchmark 的正确口径

下一位开发者不要为每个方法各跑一套口径。先做一个统一 harness，所有 receiver 共用：

```text
same clean packet
same B-wide complex AWGN realization
same Es/N0 calibration
same whole-packet IQ
same PHY parameters and expected packet length
same post-CRC exact-delivery audit
```

结果必须分成两个面板：

### Panel A：oracle-sync demod/decoder capability

所有方法使用相同 clean synchronization coordinate，只比较 symbol detector/FEC。回答“谁真正把 payload 门限推得更低”。

### Panel B：real noisy-sync end-to-end PDR

每种系统运行自己的合法同步流程，再输出完整 packet PDR。回答“实际 gateway 最终收到多少包”。

不能只画 symbol SER，也不能把某方法的 oracle sync 与另一方法的 noisy sync 混在一张 headline 图中。

统一指标：

```text
PDR vs Es/N0
PDR50 / PDR80 / PDR90
header success and payload CRC success
CRC-valid wrong delivery rate
sync estimate/candidate availability
soft-oracle gap closure
mean and p95 candidate count
CPU time, peak memory, model parameters/MACs
```

统计单位要同时报告：

```text
physical capture count
session/device/location count
noise seeds per capture
total repeated-noise trials
```

置信区间应按 physical capture/session 做 cluster bootstrap，不能把同一 capture 的 10 个 seed 当成 10 个独立 RF 场景。

## 12. 论文方法能否站住的判据

继续主推必须同时满足：

1. 在统一 full-packet benchmark 上优于 upstream native soft receiver，而不仅是优于 hard Argmax。
2. 至少多个 SF/CR 和多个独立 OTA session 上保持 PDR50/PDR80 增益。
3. ridge K=4 明显优于简单 SFD Top-K、纯 CFO bank 和相同计算量的 2D local grid。
4. candidate-0 soft、ridge-hard、ridge-soft 三者消融能分别解释 decoder gain 和 sync-list gain。
5. false delivery 有可部署的控制策略，不能只依赖 16-bit PHY CRC。
6. 在线复杂度显著低于二维搜索和神经网络 baseline，或在相同复杂度下有更高 PDR。

如果 native soft 已吃掉全部 0.8 dB decoder gain，也不是主线死亡：论文核心收缩为：

```text
ambiguity-ridge list synchronization
+ decoder-in-the-loop CRC arbitration
```

如果 ridge 在扩数据后也不能超过强 soft sync baseline，则把它降为 gr-lora_sdr 工程优化，不再作为独立论文主创新。
