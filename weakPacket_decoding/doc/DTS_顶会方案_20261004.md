# 顶会方案 v1：Structure-Aware Sync Candidate Search for Weak LoRa Packets

**日期**：2026-10-04 · **状态**：方案定稿 + 算法 v0 已实现 + 首轮证据已落地
**定位**：Decode-to-Finish Synchronization 主线的系统化收官方案；
主线 = 弱包恢复（用户三关口路线），省计算为副产品。

---

## 1. 一句话主张（论文 headline）

> 在弱 LoRa 信号下，前导同步参数的"错误"大部分**不是解码意义上的错误**：
> 固定解码器、仅替换同步参数，可救回深端 77% 的整包失败；参数空间中的
> 成功区域具有可解析的**净偏移等价结构**（ν−τ 守恒），利用该结构的候选
> 搜索在等预算下比 DeRa 式盲枚举快 2–3 倍。

## 3. 算法：DTS-Search v1 → v2

### v1（已实现，地图查表演示）
```
输入: 检测输出(dep4) + 前导参数 (ν̂, τ̂) + 解码器 D + 预算 K
1. 候选生成: net 等价类 {e_j}（代表点 = 类内最接近前导点的格点）
2. 类序: 按 |e_j − ê_0| 递增（净偏移距离）
3. 逐类评估: 代表点解码 + CRC；预算尽或成功即停
```
- 判据 = CRC16（DeRa 同款原语，判据已过负控）。
- 已知缺陷（实测）：CRC 判据太硬——自适应"代表过才展开"反而掉点
  （57% vs 77% @K=65）；类展开需软判据。

### v2（下一步实现，三个升级）
1. **软判据类展开**：代表点的 TREL 支路 margin / top1-top2 谱差作类内
   细化触发器（margin 已逐点存于 checkpoint，零新计算可先验证关联）。
2. **决策等价合并**：候选按 hard 判决（+软信息）等价分桶，桶内只评估
   一次；等价率中位 0.49 ⇒ 理论加速上限 ~2×。
3. **κ 格加密**：TREL 格 0.25→0.125 消融，对接 DTS-1 的格间失配机制，
   预期提高 argmax 类候选的鲁棒性。

### 系统集成形态（E2E）
dep4 检测（检测级全 δ 已胜 DeRa）→ DTS-search 候选级联 → TREL-5 解码
→ CRC 仲裁 → （深端）BCJR。**DTS-search 是 sync 与 demod 之间的新层**，
不改两端——这是与 DeRa（重写前端）的架构差异。

## 5. 风险与对策

| 风险 | 严重度 | 对策 |
|---|---|---|
| E2E 未胜 DeRa（δ=0 时 −22.1 领先我方） | 高 | DTS-search 直击其 E2E 优势来源（前端≈oracle 的参数选择）；D1 是裁决实验，先跑 |
| 77% vs 100% 的 23% 编码级缺口 | 中 | v2 软判据 + 多假设 FEC；如实分报"参数级可救/编码级不可救" |
| 等预算优势 2–3× 不够"漂亮" | 中 | v2 合并（理论上限 2×）叠加 ⇒ 目标 4–6×；中预算区是卖点 |
| 单批次 28 帧 | 中 | D5 扩批次；LoRadar 提供跨域 |
| CRC 误接受（多次试验后） | 低 | 28 帧固定测试图案 + GT 交叉核对已做；扩批次后按 (帧,种子) 报 GT 一致率 |
| aniso 在噪声下弱化 | 低 | 用 native/高 SNR 档展示结构、噪声档展示利用（两层证据） |
