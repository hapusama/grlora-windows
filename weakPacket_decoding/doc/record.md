<details class="lake-collapse"><summary id="ud2888aad"><span class="ne-text">流程</span></summary><p id="u4cc54900" class="ne-p"><strong><span class="ne-text">Method Overview</span></strong></p><p id="uad08d15e" class="ne-p"><span class="ne-text">本文解码流程面向低 SNR LoRa 包，整体采用“弱同步 + header-first 解码 + codec-projected Phase-MAP payload 判决”的离线增强结构。其核心思想不是直接用相位替代 LoRa 解码，而是在同步和 header 已知后，利用 LoRa 编码约束与 session payload 结构生成有限候选，再用 FFT 相位/幅度证据选择最可能的 payload 轨迹。</span></p><p id="ub955341f" class="ne-p"><strong><span class="ne-text">1. Weak Packet Synchronization Module</span></strong></p><p id="uc0472bbb" class="ne-p"><span class="ne-text">输入为原始 complex64 IQ 数据。系统首先通过滑动窗口前导码检测寻找候选 LoRa 包位置，然后使用 frame locator 和 gr-lora 风格 framesync 对候选事件进行验证。</span></p><p id="ua0a0088e" class="ne-p"><span class="ne-text">该模块输出帧级同步参数：</span></p><pre data-language="latex" id="CY3Dr" class="ne-codeblock language-latex"><code>frame start
fine payload/header start
CFO / STO / SFO estimates
framesync validity</code></pre><p id="uf21df856" class="ne-p"><span class="ne-text">只有通过 </span><code class="ne-code"><span class="ne-text">grlora_framesync_valid</span></code><span class="ne-text"> 的候选帧进入后续解码。</span></p><p id="ub8a92af5" class="ne-p"><strong><span class="ne-text">2. Header-First Demodulation Module</span></strong></p><p id="ufb7d69c9" class="ne-p"><span class="ne-text">在同步参数确定后，系统从 PHY header 起点开始解调 8 个 explicit header symbols。header 仍采用传统 FFT 幅度 argmax 判决，并经过：</span></p><pre data-language="latex" id="wPXlY" class="ne-codeblock language-latex"><code>FFT bin selection
-&gt; gray demapping
-&gt; deinterleaving
-&gt; Hamming decoding
-&gt; header checksum verification</code></pre><p id="uace9efbd" class="ne-p"><span class="ne-text">成功解出 header 后获得 payload 解码所需参数：</span></p><pre data-language="latex" id="mc1ZU" class="ne-codeblock language-latex"><code>payload_len, CR, has_crc, LDRO</code></pre><p id="u5b2f5958" class="ne-p"><span class="ne-text">这些参数决定后续 payload symbol 数量和 codec 重编码路径。</span></p><p id="u5b1e2512" class="ne-p"><strong><span class="ne-text">3. Packet-Local Phase Model Module</span></strong></p><p id="u6a0f6493" class="ne-p"><span class="ne-text">系统从</span><strong><span class="ne-text">已知语义的 preamble bin 和已解出的 header symbols 中提取 FFT 复数相位（更多地会去使用header symbols，因为preamble好像就是和payload部分固定差一个slope）</span></strong><span class="ne-text">，拟合包内相位线：</span></p><pre data-language="latex" id="GVrcY" class="ne-codeblock language-latex"><code>theta_k = a k + b</code></pre><p id="u0d1d618b" class="ne-p"><span class="ne-text">其中 </span><code class="ne-code"><span class="ne-text">k</span></code><span class="ne-text"> 为 symbol index，</span><code class="ne-code"><span class="ne-text">theta_k</span></code><span class="ne-text"> 是第 </span><code class="ne-code"><span class="ne-text">k</span></code><span class="ne-text"> 个 payload symbol 对应正确 bin 的预测相位。该相位模型用于衡量候选 FFT bin 是否符合包内相干轨迹。</span></p><p id="u57c65de9" class="ne-p"><strong><span class="ne-text">4. Payload FFT Evidence Extraction Module</span></strong></p><p id="u9355dace" class="ne-p"><span class="ne-text">对每个 payload symbol，系统按同步参数执行 dechirp 和 FFT，保留完整频域证据：</span></p><pre data-language="latex" id="kAdnc" class="ne-codeblock language-latex"><code>Z[k, b]</code></pre><p id="uc704c31a" class="ne-p"><span class="ne-text">其中 </span><code class="ne-code"><span class="ne-text">k</span></code><span class="ne-text"> 是 payload symbol index，</span><code class="ne-code"><span class="ne-text">b</span></code><span class="ne-text"> 是 FFT bin。后续判决不只使用最大幅度 bin，而是同时使用：</span></p><pre data-language="latex" id="abtya" class="ne-codeblock language-latex"><code>|Z[k,b]|       amplitude evidence
angle(Z[k,b]) phase evidence</code></pre><p id="u38c32932" class="ne-p"><strong><span class="ne-text">5. Payload Codec Projection Module</span></strong></p><p id="ue38ee00d" class="ne-p"><span class="ne-text">为了避免逐 symbol 独立误判，系统引入 codec projection。对一个 payload byte 候选 </span><code class="ne-code"><span class="ne-text">c</span></code><span class="ne-text">，使用 </span><code class="ne-code"><span class="ne-text">payload_codec.py</span></code><span class="ne-text"> 复刻 gr-lora_sdr PHY 编码链：</span></p><pre data-language="latex" id="TFbjJ" class="ne-codeblock language-latex"><code>payload bytes
-&gt; whitening
-&gt; CRC
-&gt; Hamming encoding
-&gt; interleaving
-&gt; gray demap
-&gt; expected LoRa symbols</code></pre><p id="u59ce7237" class="ne-p"><span class="ne-text">该模块输出候选 payload 对应的理论 symbol/bin 轨迹。也就是说，搜索对象从单个 FFT bin 变为“符合 LoRa 编码结构的 payload 候选”。</span></p><p id="ueba9e09d" class="ne-p"><strong><span class="ne-text">6. Phase-MAP Candidate Scoring Module</span></strong></p><p id="u56df7559" class="ne-p"><span class="ne-text">对于候选 payload </span><code class="ne-code"><span class="ne-text">c</span></code><span class="ne-text">，其重编码得到的第 </span><code class="ne-code"><span class="ne-text">k</span></code><span class="ne-text"> 个 symbol 对应 bin 记为 </span><code class="ne-code"><span class="ne-text">b_c,k</span></code><span class="ne-text">。系统在真实 FFT 证据中读取 </span><code class="ne-code"><span class="ne-text">Z[k,b_c,k]</span></code><span class="ne-text">，并计算相位似然：</span></p><pre data-language="latex" id="Qew9J" class="ne-codeblock language-latex"><code>L_phase(c) = kappa / |K(c)| * sum_k cos(angle(Z[k,b_c,k]) - theta_k)</code></pre><p id="uf9af73ed" class="ne-p"><span class="ne-text">其中 </span><code class="ne-code"><span class="ne-text">theta_k</span></code><span class="ne-text"> 来自包内 phase line，</span><code class="ne-code"><span class="ne-text">kappa</span></code><span class="ne-text"> 控制对相位证据的信任程度。候选总分还可结合幅度项和平滑相位线拟合项：</span></p><pre data-language="latex" id="Q6awU" class="ne-codeblock language-latex"><code>L(c) = phase likelihood + amplitude likelihood + trajectory smoothness</code></pre><p id="u7fd52fbe" class="ne-p"><span class="ne-text">最终选择得分最高的 payload 候选。</span></p><p id="u521d37d6" class="ne-p"><strong><span class="ne-text">7. Residual Byte Search Module</span></strong></p><p id="u0ace2b9d" class="ne-p"><span class="ne-text">若 session template 已知大部分 payload 字节，仅少数字节未知，系统枚举未知 residual byte：</span></p><pre data-language="latex" id="PgxdA" class="ne-codeblock language-latex"><code>unknown byte in [0, 255]</code></pre><p id="u170f93d3" class="ne-p"><span class="ne-text">每个枚举值都会生成一个完整 payload 候选，再经 codec projection 和 Phase-MAP scoring 评分。该模块把低 SNR 下的 symbol 判决问题转化为受编码约束的 payload 候选搜索问题。</span></p><p id="u336bcbd1" class="ne-p"><strong><span class="ne-text">8. Joint Session Trajectory Module</span></strong></p><p id="u34c3ca41" class="ne-p"><span class="ne-text">对于多个 packet，系统进一步利用 session 中动态字节的规律。例如当前实验中使用 affine byte trajectory：</span></p><pre data-language="latex" id="l1QnX" class="ne-codeblock language-latex"><code>byte_value(packet_index) = slope * packet_index + intercept mod 256</code></pre><p id="u82dd1cc2" class="ne-p"><span class="ne-text">joint decoder 搜索全局 </span><code class="ne-code"><span class="ne-text">(slope, intercept)</span></code><span class="ne-text">，最大化多个 packet 的候选得分总和，从而提升单包候选模糊时的 app-level 恢复稳定性。</span></p><p id="u42c6f839" class="ne-p"><strong><span class="ne-text">Summary</span></strong></p><p id="uad06ebc1" class="ne-p"><span class="ne-text">整体流程可以概括为：</span></p><pre data-language="latex" id="dnFEd" class="ne-codeblock language-latex"><code>IQ
-&gt; weak synchronization
-&gt; header-first decoding
-&gt; phase-line estimation
-&gt; payload FFT evidence extraction
-&gt; payload candidate re-encoding
-&gt; Phase-MAP scoring
-&gt; residual byte selection
-&gt; joint session decoding
-&gt; recovered payload</code></pre><p id="u52e52ca2" class="ne-p"><span class="ne-text">该方法的关键是：</span><strong><span class="ne-text">同步和 header 解码保持传统流程；payload 判决不再依赖逐 symbol argmax，而是通过 LoRa codec 约束生成候选，再用相位/幅度证据选择最合理的整包轨迹。</span></strong></p></details>
**相位拟合**：它先在“已知正确 bin”的位置取 FFT 复数值的相位，也就是 preamble 的 bin 0 和 header 已解出 symbol 对应的 bin，相位用 `angle(FFT[bin])` 得到；然后把这些相位按 symbol 时间顺序做 `unwrap`，避免 `-pi/pi` 跳变；再**用最小二乘拟合一条直线 **`**theta_k = a k + b**`，其中 `k` 是包内 symbol 的绝对索引，`theta_k` 是相位。代码里实际更偏向用 header anchors 拟合这条线：header 点够两个就用 header line，preamble 更多是兜底，因为 preamble 到 payload 的相位斜率可能有系统偏差。后面解 payload 时，不是用 payload 真值拟合线，而是用这条线预测每个 payload symbol 的正确 bin 应该落在哪个相位轨迹上，再看候选 bin 的相位残差是否贴近这条线。

**Codec 的作用就是**：**枚举未知的 payload bytes，并和已知 payload template 拼成一个个候选 payload。**每个候选经过 LoRa 编码链重编码后，可以得到它对应的理论 FFT bin 序列。注意，这一步只得到“应该落在哪些 bin”，并不能预测完整频谱，也不能预测真实相位和幅度。真实相位/幅度仍然来自前面保存的 FFT 证据。之后系统按候选给出的 bin 序列，**到真实 FFT 里取对应 bin 的幅度和相位，并计算打分**。单个 symbol 的分数主要看两点：该 bin 幅度是否强、相位是否贴合拟合出的相位线。所有 payload symbols 的分数累加或平均后，就是这个候选 payload 的总分。最后，如果是单包解码，就选总分最高的候选；如果开启跨包 joint decoding，就选跨多个包总分最高且满足轨迹规律的候选序列。

目前这个aigc方案最垃圾的就是这里了，他有一个**很强的先验就是“每一次的payload只有几个symbol会变，其他都是固定的”，其实也可以讲故事用上这点，比如说lora节点进行数据上报的时候（其实就相当于很多anchor了），但是先别这么搞吧。**


2. 打分算法：

<details class="lake-collapse"><summary id="u00207900"><span class="ne-text">包内打分算法</span></summary><p id="u80f13b6d" class="ne-p"><span class="ne-text">1. 候选 payload 经过 LoRa codec 重编码</span></p><p id="u8aaacdbe" class="ne-p"><span class="ne-text">   得到每个相关 symbol 的理论 bin：b_c,k</span></p><p id="ucb1f67ac" class="ne-p"><span class="ne-text"></span></p><p id="u1b7d84ba" class="ne-p"><span class="ne-text">2. 到真实 FFT 证据里取这个 bin：</span></p><p id="u728c68ee" class="ne-p"><span class="ne-text">   z_k = Z[k, b_c,k]</span></p><p id="ue5b61ebd" class="ne-p"><span class="ne-text"></span></p><p id="u3587043c" class="ne-p"><span class="ne-text">3. 计算相位残差：</span></p><p id="u17e7f70c" class="ne-p"><span class="ne-text">   r_k = wrap(angle(z_k) - theta_k)</span></p><p id="u0f51bb0c" class="ne-p"><span class="ne-text"></span></p><p id="u1e529d02" class="ne-p"><span class="ne-text">4. 计算相位分：</span></p><p id="uf1b46cfd" class="ne-p"><span class="ne-text">   phase_score_k = 0.5 + 0.5*cos(r_k)</span></p><p id="u047c6049" class="ne-p"><span class="ne-text"></span></p><p id="ued859fbb" class="ne-p"><span class="ne-text">5. 计算幅度分：</span></p><p id="u2f334b2b" class="ne-p"><span class="ne-text">   amp_score_k = |z_k|^2 / max_b |Z[k,b]|^2</span></p><p id="u4a8e6753" class="ne-p"><span class="ne-text"></span></p><p id="u160cf6c7" class="ne-p"><span class="ne-text">6. 对候选选中的这些相位点再拟合一条线，</span></p><p id="u85178ca3" class="ne-p"><span class="ne-text">   得到 line_rmse_pi</span></p><p id="u46d344fd" class="ne-p"><span class="ne-text"></span></p><p id="u01a9bc07" class="ne-p"><span class="ne-text">7. 得到轨迹平滑分：</span></p><p id="uf90e1213" class="ne-p"><span class="ne-text">   line_score = exp(-(line_rmse_pi / 0.30)^2)</span></p><p id="u23ef1265" class="ne-p"><span class="ne-text"></span></p><p id="ua4708275" class="ne-p"><span class="ne-text">8. 综合打分：</span></p><p id="u551a7ecf" class="ne-p"><span class="ne-text">   score =</span></p><p id="ud13affbc" class="ne-p"><span class="ne-text">     0.25 * mean(phase_score)</span></p><p id="uce42a891" class="ne-p"><span class="ne-text">   + 0.50 * line_score</span></p><p id="u622fc059" class="ne-p"><span class="ne-text">   + 0.20 * mean(amp_score)</span></p><p id="u66f5f173" class="ne-p"><span class="ne-text">   + 0.05 * profile_score</span></p></details>
<details class="lake-collapse"><summary id="u561d20dc"><span class="ne-text">跨包+byte线性变化先验（计数器来的）</span></summary><p id="uf356df84" class="ne-p"><span class="ne-text">跨包打分不再重新算 FFT/相位，它直接使用单包阶段已经算好的候选分数。</span></p><p id="u37f0b1d4" class="ne-p"><span class="ne-text">单包阶段输出的是：</span></p><pre data-language="plain" id="XZmPV" class="ne-codeblock language-plain"><code>packet i, byte value v -&gt; score_i(v)</code></pre><p id="ue4dd82c4" class="ne-p"><span class="ne-text">跨包假设某个未知 byte 满足：</span></p><pre data-language="plain" id="CxFxL" class="ne-codeblock language-plain"><code>v_i = slope * packet_index_i + intercept mod 256</code></pre><p id="uf463b047" class="ne-p"><span class="ne-text">然后枚举所有 </span><code class="ne-code"><span class="ne-text">(slope, intercept)</span></code><span class="ne-text">，对每一条轨迹算总分：</span></p><pre data-language="plain" id="heY8l" class="ne-codeblock language-plain"><code>joint_score(slope, intercept)
= sum over packets i score_i(v_i)</code></pre><p id="ud4bea1e6" class="ne-p"><span class="ne-text">也就是：</span></p><pre data-language="plain" id="IdaBO" class="ne-codeblock language-plain"><code>joint_score(a,b)
= sum_i score_i((a*i + b) mod 256)</code></pre><p id="u4c9bf1c3" class="ne-p"><span class="ne-text">最后选择：</span></p><pre data-language="plain" id="OJVSt" class="ne-codeblock language-plain"><code>(a,b)* = argmax joint_score(a,b)</code></pre><p id="u73bb2fd8" class="ne-p"><span class="ne-text">选出来以后，每个包的 byte 就是：</span></p><pre data-language="plain" id="shbSH" class="ne-codeblock language-plain"><code>v_i = (a*packet_index_i + b) mod 256</code></pre><p id="ub30bdc7f" class="ne-p"><span class="ne-text">所以跨包打分本质是：</span></p><pre data-language="plain" id="d6ZhQ" class="ne-codeblock language-plain"><code>把“每个包每个 byte 候选的单包分数表”
套上一条线性 byte 轨迹，
然后把这条轨迹经过的候选分数加起来。</code></pre><p id="u48fa0354" class="ne-p"><span class="ne-text">它没有再拟合相位线，也没有再看频谱。相位/幅度信息已经被压缩进 </span><code class="ne-code"><span class="ne-text">score_i(v)</span></code><span class="ne-text"> 里了。</span></p></details>
<details class="lake-collapse"><summary id="u36cdce27"><span class="ne-text">phase map效果好的原因</span></summary><p id="ubbe28a3c" class="ne-p"><span class="ne-text">看起来很好，但要注意它统计的不是“整个 payload 的 SER”，而是</span><strong><span class="ne-text">residual search 相关 symbols 的 SER</span></strong><span class="ne-text">，而且是在强先验下算的。</span></p><p id="u849932c2" class="ne-p"><span class="ne-text">它好的原因主要有三个：</span></p><ol class="ne-ol"><li id="u0f54dd90" data-lake-index-type="0"><strong><span class="ne-text">搜索空间被极大压缩了</span></strong></li></ol><p id="ubb95295f" class="ne-p"><span class="ne-text">不是全 payload 盲解，而是：</span></p><pre data-language="plain" id="RkrMs" class="ne-codeblock language-plain"><code>只枚举 payload[6] = 0..255
其它 32 bytes 已知</code></pre><p id="uba0ffa43" class="ne-p"><span class="ne-text">所以系统不是在几乎无限大的 symbol 空间里找答案，而是在 256 个合法候选里选一个。</span></p><ol start="2" class="ne-ol"><li id="u4cc1fe33" data-lake-index-type="0"><strong><span class="ne-text">一个 byte 会影响多个 LoRa symbols</span></strong></li></ol><p id="u7d73f8ba" class="ne-p"><span class="ne-text">当前配置下，</span><code class="ne-code"><span class="ne-text">payload[6]</span></code><span class="ne-text"> 通过 LoRa 编码/交织后，会影响前面大约 </span><code class="ne-code"><span class="ne-text">10</span></code><span class="ne-text"> 个 payload symbols。<br /></span><span class="ne-text">所以 Phase-MAP 不是只看一个 FFT bin，而是：</span></p><pre data-language="plain" id="mCxVj" class="ne-codeblock language-plain"><code>一个候选 byte -&gt; 一串 expected bins
-&gt; 多个 symbols 的幅度/相位一起投票</code></pre><p id="ufd88fa41" class="ne-p"><span class="ne-text">这比逐 symbol argmax 稳很多。</span></p><ol start="3" class="ne-ol"><li id="u7b252beb" data-lake-index-type="0"><strong><span class="ne-text">它用了相位线，不只看幅度峰值</span></strong></li></ol><p id="u71fa2b85" class="ne-p"><span class="ne-text">低 SNR 下，最大幅度 bin 很容易被噪声抢走。<br /></span><span class="ne-text">Phase-MAP 会看候选 bin 的相位是否贴合包内相干轨迹：</span></p><pre data-language="plain" id="rDFC0" class="ne-codeblock language-plain"><code>r_k = angle(Z[k,b]) - theta_k
phase_score ~= cos(r_k)</code></pre><p id="ubab1fd4d" class="ne-p"><span class="ne-text">也就是说，即使某个候选 bin 不是最大幅度，只要它在相位轨迹上更一致，也可能被选中。</span></p><p id="ue0cfc95c" class="ne-p"><span class="ne-text">所以 </span><code class="ne-code"><span class="ne-text">Phase-MAP residual SER = 0.04 / 0.1086 / ...</span></code><span class="ne-text"> 的含义更像：</span></p><pre data-language="plain" id="GOJUf" class="ne-codeblock language-plain"><code>在 payload 大部分已知、只剩一个 counter byte 未知的情况下，
用 codec 约束 + 多 symbol 证据 + 相位一致性，
能比逐 symbol argmax 更好地判断这个 residual byte 相关的 symbols。</code></pre><p id="u0a64bf58" class="ne-p"><span class="ne-text">它不是说：</span></p><pre data-language="plain" id="bOB6D" class="ne-codeblock language-plain"><code>整个 LoRa payload 在 -27 dB 下还能 80% 正确盲解</code></pre><p id="u1d45801e" class="ne-p"><span class="ne-text">这个千万不能这么理解。</span></p></details>
