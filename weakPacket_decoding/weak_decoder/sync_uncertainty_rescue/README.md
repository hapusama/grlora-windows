# SUR（Sync-Uncertainty Rescue）—— 保留同步不确定性的相干弱包解码器

**一句话 idea**：弱信号下前导同步注定不完美；与其把它估得更准（DeRa 的路），
不如**保留同步不确定性当作一个小候选集合，在每个物理一致的假设下做充分
相干解码，让 payload 判决参与选择解释**——同步做到"解码能完成为止"。

**主线故事**：DeRa（MobiCom'26）的两段相干合并是这个问题在"点估计"特例下
的解；我们是保留不确定性的通解。它的 5 候选重试天花板把它锁在 79.8%，
同引擎换判决引导调度推到 97.6%（−24 dB，真实 OTA）。

## 与 D2F_20261005 档案包的关系（防混淆，先读）

隔壁 `weak_decoder/D2F_20261005/` = **系统链线**（Decode-to-Finish 系统名，
用户拍板论文统一用名）：dep4k16 检测 × 连续锚 × 双列仲裁 × 斜率梯的代码
与战报全量快照，管的是**检测/同步层**。
本目录 `sync_uncertainty_rescue/` = **候选救援线**（SUR）：前导给定后的
同步不确定性 → 候选集合 → 相干解码 → 判决引导调度，管的是**解码器内**。
两条线互补，最终在 E2E 全链合流（见 03_ROADMAP P2-1）。**本线不使用
D2F 缩写**，以免与系统名冲突。

## 战绩口径（用户裁定，违者作废）

**只认 SER/PER**。检测级一切 dB 数（cert +4dB / dep4 / FF_cert8）只作
诊断归因，不得写作"胜 DeRa"。对 DeRa 实体：SER 口径落后 ~1 dB（实验B），
E2E PER 未胜；**本路线（W3）是首个同引擎同预算下大幅超越其架构上限的
正面结果（97.6% vs 79.8% 总整包恢复率，代理臂，待去代理化）**。
